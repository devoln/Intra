# Архитектура Intra / IntraSynth — карта для агента

Дата: 2026-09-25
Роль документа: **единственная точка входа в проект**. Читается вместо обхода
репозитория (`glob`/`grep` по всему дереву) в начале сессии.
Живость карты проверяется скриптом: `node intrasynth/tools/agent/orient.mjs --check`
— он убеждается, что каждый путь и каждая команда, упомянутые здесь и в скиллах,
ещё существуют. Если `--check` красный, правьте карту, а не подгоняйте реальность.

Правила самого проекта (C++-стиль, запрет stdlib, `constexpr`-first и т.д.) лежат в
`intrasynth/docs/Rules.md` и здесь не дублируются.

## 1. Что это за проект

| слой | что это | где |
|---|---|---|
| ядро | `Intra` — C++20 библиотека без стандартной библиотеки (свой `Toolchain.h`, SIMD, контейнеры, математика, аудио-буферы) | `Intra/` |
| синтезатор | `IntraSynth` — GM-совместимый синтезатор (фортепиано, гитары, флейты, хор, пэды) поверх ядра, собирается в WebAssembly | `intrasynth/` |
| веб | плеер в браузере: `AudioWorklet`, MIDI-файлы, панель A/B-рендеров, вкладки сэмплов владельца | `intrasynth/web/`, `dist/` |
| инструментовка | весь офлайн-фиттинг под банк «Titanic 200 GM-GS v1.2.sf2»: библиотека анализа, CLI замеров, генераторы | `intrasynth/tools/` |
| история и правила | решения, ворклоги апдейтов, правила | `intrasynth/docs/` |

Продукт владельца — **звук**. Приёмка почти всегда ушами; замер только сужает
варианты. Поэтому любая правка тембра заканчивается рендером в панель A/B и
строкой в ворклоге, а не только зелёным замером.

## 2. Карта каталогов (важно: часть репозитория не видна инструментам поиска)

`git` игнорирует рабочие каталоги, и **любой инструмент поиска по файлам, который
уважает `.gitignore`, их не покажет** — их надо знать по этой таблице, а не искать:

| каталог | в git | что внутри | почему важно |
|---|---|---|---|
| `scripts/` | **нет** | каноническая сборка `build-wasm.sh`, стейджинг `build-web.js`, dev-сервер `serve.js`, смоук `smoke-test-wasm.mjs`, генераторы `generate-sf2-samples.js` / `generate-piano-regions.js`, исторические одноразовые зонды `_tmp-*` | AGENTS.md ссылается на файлы отсюда; в листинге репозитория их не будет |
| `intrasynth/web/generated/` | **нет** | артефакты: `IntraSynth.wasm`, `IntraSynth.js`, `samples/` (вкладки владельца), `ab/` (A/B-рендеры); аудио обеих панелей — **FLAC** (Update 196, ~95 МБ вместо ~308 МБ WAV) | замеры и панель читают ровно эти файлы |
| `dist/` | **нет** | собранный веб-бандл; `build-web.js` стирает его целиком при каждом запуске | не хранить в нём ничего руками |
| `.scratch/` | **нет** | черновые зонды, снимки сборок `.scratch/ab-builds/<id>/`, выгрузки | снимки сборок — **не мусор**, из них воспроизводится «до/после» |
| `node_modules/` | **нет** | только `playwright` для локальных зондов | |

Всё остальное (`Intra/`, `intrasynth/` включая `intrasynth/web/*.html|*.js` и
`intrasynth/docs/`, `intrasynth/.agents/`, `AGENTS.md`, `package.json`) версионируется.

Синтезатор готовится к выносу в собственный репозиторий: `intrasynth/` уже несёт свои
документы, веб-плеер и агентское хозяйство (`intrasynth/docs/`, `intrasynth/web/`,
`intrasynth/AGENTS.md`, `intrasynth/.agents/`); корневые `scripts/`, `dist/` и
`.scratch/` переедут вместе с ним при разделении.

## 3. Как звук проходит через код

```
MIDI (SMF/живой источник)
  └─ MidiSynth            MidiSynth.{h,cpp}          выбор инструмента по программе/каналу
      └─ MusicSynthesizer MusicSynthesizer*.cpp      полифония, эффекты, микс
          └─ NoteSampler  NoteSampler.{h,cpp}        ГОЛОС: список сэмплеров + огибающая
              ├─ AdditiveSampler      AdditiveSampler.{h,cpp}      PADsynth: таблица + широкие гармоники
              ├─ WaveTableSampler     WaveTableSampler.{h,cpp}     чтение вейвтейбла, петли
              ├─ WaveFormSampler      WaveFormSampler.{h,cpp}      таблица по формуле (согласные)
              ├─ SpectralStringSampler SpectralStringSampler.{h,cpp} модальная струна + тракт
              ├─ KarplusStrongSampler / GaussianStringSampler / DrumPhysicalModel / RecordedSampler
              └─ NoiseSampler         Synth.h                    «дыхание»/«воздух»: таблица шума + ФНЧ/ФВЧ
  └─ EmscriptenInterface  EmscriptenInterface.cpp    C-API для WASM: _SourceCreateLive, _SourceSendMidiEvent, _SynthSet… (только для зондов)
```

Профили инструментов (это и есть «звук как данные») живут в
`intrasynth/src/Intra/Synth/InstrumentLibrary.cpp` — 3 300 строк на все GM-программы:
таблицы гармоник, ширины, шумовые слои, огибающие, регионы по клавиатуре. Правка
тембра почти всегда начинается и заканчивается здесь.

| файл | что решает |
|---|---|
| `InstrumentLibrary.cpp` | сами числа инструментов: профили гармоник, шум, атака, регионы |
| `Synth.h` | генераторы и их ядра: `NoiseSampler`, `VibratoLfo` (вибрато/тремоло), общие сэмплерные интерфейсы |
| `AdditiveSampler.{h,cpp}` | как из профиля получается таблица: `AddSineHarmonicGauss`, ширина `b(k)`, нормировка |
| `NoteSampler.{h,cpp}` | микс слоёв голоса, огибающие, реlease, `SoundReleaseKill` |
| `Envelope.h`, `ADSR.h`, `ExponentialAttenuation.h` | огибающие и их сегменты |
| `ComputeKernels.h` | SIMD-ядра (в том числе блочные LFO) |
| `MusicalInstrument.{h,cpp}` | сборка сэмплеров из профиля при note-on |
| `EmscriptenInterface.cpp` | экспорт в WASM; здесь же отладочные ручки |

## 4. Канонические команды

Запускать **из корня репозитория** (все пути в скриптах относительные).

| что | команда |
|---|---|
| ориентировка (в начале сессии) | `node intrasynth/tools/agent/orient.mjs` |
| сборка канона | `sh scripts/build-wasm.sh` |
| стейджинг веб-плеера | `node scripts/build-web.js` |
| проверка живости сборки | `node scripts/smoke-test-wasm.mjs` |
| самопроверка анализа | `node intrasynth/tools/analysis/cli.mjs selftest` |
| замер (наш vs банк) | `node intrasynth/tools/analysis/cli.mjs <vib\|trem\|mod\|spec\|bands\|timbre\|pitch\|period\|floor\|env\|attack> prog:key` |
| единый отчёт по инструменту | `node intrasynth/tools/analysis/fit-report.mjs prog:key [prog:key …]` |
| A/B-панель для владельца | `node intrasynth/tools/ab/render-ab.mjs` (при нужде `--force`); файлы — `<slug сборки>.<хеш>.flac`; манифест — ВКЛАДКА НА ИНСТРУМЕНТ, внутри ноты, внутри ДАТЫ по МСК `YYYY-MM-DD`, свежие сверху, повторы (тот же файл = звук не менялся в этом апдейте) не попадают, а в каталоге `ab/` остаётся ровно то, что видно в панели |
| dev-сервер | `node scripts/serve.js` (на 0.0.0.0, порт из `PORT`) |

Конфигурация канона и обязательный отчёт о размере WASM описаны в `AGENTS.md`
(раздел про WASM build mandate) — не пересказываю, там же и запрет `-Oz`.

## 6. Инварианты, которые уже кусали (не перепроверять с нуля)

1. **Время в замерах — от NOTE-ON.** Note-on стоит не на нуле файла; окна, отсчитанные
   от начала рендера, читают тишину.
2. **Программа синтезатора ≠ пресет банка.** Сопоставление — в `lib/render.mjs`
   (`BANK_PROGRAM`); «эталон» по неверной программе семь апдейтов подряд вёл подгонку
   флейты по контрабасу.
3. **Петля таблицы даёт два разных дефекта, и лечатся они по-разному.** Лупнутая
   таблица даёт корреляцию на лаге ровно N семплов. Если гармоники широкие и их
   юбки перекрываются, случайные фазы складываются в блуждающую огибающую —
   слышно как медленное КАЧАНИЕ ровно на fs/N (2.69 Гц при N = 16384). Если же
   спектр — линии (узкие гармоники), качания нет вовсе: то, что слышно как
   «биения», даёт энсамбль, и длина таблицы тут ни при чём (`f0·Δ/1731`).
   **N — поле пресета** (`TableLength` у `VoicePresetSpec`, Update 190): 32768
   у 50/51/52, 16384 у 53/54/91/94. Удвоение N вдвое замедляет качание
   (371 → 742 мс), но перекашивает ТЕМБР у широких пресетов: юбка размазана по
   N·bwi бинам с некогерентными фазами и растёт как √N (+3 дБ на удвоение), а
   узкие линии и нормировка `amplSum` от N не зависят. Владелец выбрал 32768
   УХОМ (кандидат 188), поэтому это решение, а не недосмотр; 65536 отклонён в
   Update 174 — перекос растёт дальше. Выравнивание огибающей по кольцу
   (`FlattenTableLoop`, Update 189) владелец ОТКЛОНИЛ («делает ещё хуже») —
   кода этой правки в репозитории больше нет.
   `intrasynth/docs/tasks/active/20260926-VoiceFamilyArcLog.md` (§5, §12).
4. **Ширина гармоник задаётся ФОРМОЙ по k, и у каждого пресета своей** (`BwSlope`
   в `VoicePresetSpec`): `b(k) = 52·k` центов у 52 ChoirAahs, `b(k) = 5·k` у
   51 SynthStrings2 (в 189 было 8·k: ширина стоит ПРОФИЛЮ дБ, потому что юбка
   отбирает у линии пик — замер 191: 8·k давало расхождение профиля 4.6-8.1 дБ,
   5·k — 1.1-5.6), прежняя `bwHiCents·clamp((k−8)/20)` у 50/53/54/91/94. У банка
   ширина примерно постоянна в центах (σ в герцах растёт с k), поэтому константа
   её не описывает. Энсамбль хора при этом СНЯТ (Update 188) — слово владельца
   важнее меры «привязки к лупу»: `intrasynth/docs/tasks/active/20260926-VoiceFamilyArcLog.md` (§5, §12).
5. **Две симметричные расстройки — это ОДНА пара биений с доминантой**, и её частота
   равна `f0·Δ/1731` — то есть растёт и с клавишей,и с расстройкой («сильные биения» на C5+). Лечится числом певцов, НЕрегулярным
   шагом, своим дрожанием
   вибрато (94 Pad7Halo в Update 181, 50 SynthStrings в 188) иСУЖЕНИЕМ разброса (Update 189). Ширина спектра и движение — РАЗНЫЕ
   рычаги: ширину даёт таблица (`BwSlope`), движение — энсамбль.
6. **Шум И СОГЛАСНАЯ — форма в герцах, а не по номеру гармоники.** Наклон шума и
   форма согласной задаются в герцах: на сетке гармоник форма уезжает с клавишей
   (у согласной 53 излом стоял на 195 Гц на C2 и на 1.6 кГц на C6 — одна и та же
   «Т» звучала по-разному). С Update 191 согласная — не один наклон, а
   **ФОРМАНТЫ** в герцах (`BurstFormant`: центр/ширина/уровень), а её огибающая
   ЗАДЕРЖАНА: /t/ — это взрыв с подъёмом за 2-3 мс, а не мгновенный спайк.
   Мгновенный фронт слышен как высокий цифровой щелчок даже когда верх ослаблен,
   а ПЛОСКИЙ континуум из равных широких гармоник слышен как белый шум — то и
   другое владелец назвал в Update 191. Работающее число: задержка 1.5 мс, атака
   2 мс, спад 20 мс; спад 30-34 мс уже возвращает шум, спад 12 мс — щелчок
   (замеры в коротких окнах: 1 мс — `.scratch/u191-t53-onset.mjs`, 2-4 мс —
   `.scratch/u191-atk53.mjs`).
   `intrasynth/docs/tasks/active/20260926-VoiceFamilyArcLog.md` (§12, хронология 191).
7. **`BuildWaveTable` нормирует на сумму амплитуд, а громкость даёт RMS.** Правка
   профиля меняет и нормировку, и уровень — компенсируйте `VolumeScale` по RMS
   (в Update 188 снятие певцов у хора стоило 8.18 дБ: `Volume` 0.1043 → 0.2674).
8. **Перевод дБ→амплитуда — `20·log10(2) = 6.0206`.** Подстановка дБ прямо в показатель
   степени двойки ослабляла верх в 6 раз сильнее задуманного.
9. **`SineRange` вырождается ниже ~4 Гц** (округление `2 − mK` до 2.0 даёт линейный
   рост). Для медленных огибающих — фазовый аккумулятор.
10. **Спектр тела обрывается на 48-й гармонике — то есть на 48·f0, а не на 20 кГц.**
   `kProfileHarmonics = 48`, и «воздух» до Update 191 заканчивался там же
   (`kAirLastK = 47.5`). На C3 это 6.3 кГц, на C2 — 3.1 кГц, поэтому НИЗКИЕ ноты
   глухие у ВСЕХ голосовых пресетов (замер `cli.mjs bands`, полоса 4800-9600 Гц:
   51:48 −131.1 против банковских −91.4, 53:48 −107.1 против −63.5, 52:48 −129.6
   против −50.9, 50:48 −131.9 против −98.0). Верх «воздуха» теперь ПОЛЕ ПРЕСЕТА
   (`kVoiceAirTopK`; у 51 — до Найквиста, у 53/54/91/94 остался 47.5 и их выход
   бит-в-бит прежний). Верхние полосы банка НЕ значит «добавить шума вообще»: у 50
   середина уже на 8-11 дБ горячее банка, поэтому уровень и наклон «воздуха»
   калибруются по полосам банка ПО КАЖДОМУ пресету (у 51 −31 дБ и 14 дБ/окт).
   `intrasynth/docs/tasks/active/20260926-VoiceFamilyArcLog.md` (§12).
11. **Обе панели отдаются FLAC, и перекодирование обязано быть бит-в-бит.** Кодек
   (`libflacjs`) живёт только в Node-инструментах — браузер декодирует FLAC нативно,
   во фронтенде библиотеки нет. Ловушка при миграции: значение `-32768` не проходит
   через нормировку ±1 (clamp даёт −32767), поэтому уже оцифрованный PCM кодируется
   `flacEncodeInt16`, а результат сверяется с исходным побитно; в двух файлах панелей
   `-32768` есть. Имена A/B-файлов сохранили схему (`<slug>.<хеш>.flac`) — на хеше
   содержимого держится дедупликация панели.
   `intrasynth/docs/tasks/active/20260926-VoiceFamilyArcLog.md` (§12).
12. **Пол хоровой семьи калибруется профилем по фазе внутри f0, а не медианой между
   гармониками.** Медиана не различает два разных явления: у 52 банк спадает от линии
   наружу на 34 дБ (юбки гармоник, тембр), у 54/91/94 держит ровную полку (тот самый
   «шум-гул»), а числа у обоих сходятся. Поэтому у 52 работают ЮБКИ — размытые копии
   гармоник (`kVoiceAirMode` = 2), у 54/91/94 — сетка Update 195, а правятся у них
   только уровень, наклон по клавише и горб (`u198-probe.mjs`: RMS профиля 52 упала с
   20-26 до 3-7 дБ, у 53 с 11-15 до 3,8-6,2). Механизм копий был снят в Update 197 не
   из-за идеи, а из-за отсутствия компенсации 1/σ ядра: `AddSineHarmonicGauss` хранит
   интеграл гауссианы, поэтому вершина линии ∝ `amp/σ` — и копия шириной 700-1400
   центов тонула на 20-45 дБ. Тот же делитель объясняет второе правило: ширина гармоник
   тела при `bwSlope > 0` ПОСТОЯННАЯ в центах, а растущая `52·k` съедала хвост профиля
   у 52 (h5 −28 дБ против банковских −15).
   `intrasynth/docs/tasks/active/20260926-VoiceFamilyArcLog.md` (§5, §12).

## 7. Чего не делать

- Не заводить белый шум без разрешения по классу инструмента: струны — запрет,
  флейты — только с полосными замерами против Titanic, ударные и эффекты — норма
  (`intrasynth/docs/tasks/active/20260926-VoiceFamilyArcLog.md`, §12).
- Не менять конфигурацию сборки и не докладывать размер WASM — это мандат в `AGENTS.md`.
- Не складывать артефакты в корень: временное — в `.scratch/`, ничего `build-*/` и
  `probe-*` рядом с `AGENTS.md`.
- Не писать анализ копипастой в `.scratch/`: одна реализация БПФ в
  `intrasynth/tools/analysis/lib/fft.mjs` под `selftest`.
- Не отдавать панели владельца как WAV и не пережимать их кодеком с потерями:
  по этим файлам идёт приёмка НА СЛУХ (атака, щелчки, согласные).
  `intrasynth/docs/tasks/active/20260926-VoiceFamilyArcLog.md` (§12).
- Не класть в панель A/B кандидата, у которого замер не показывает изменения, и не
  оставлять отклонённый механизм кандидатом: вкладка инструмента должна читаться как
  список настоящих изменений звука.
  `intrasynth/docs/tasks/active/20260926-VoiceFamilyArcLog.md` (§12).
