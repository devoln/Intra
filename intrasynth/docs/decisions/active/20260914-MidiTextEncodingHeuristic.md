# Решение

## Что решено

Имя дорожки в SMF (meta-событие `FF 03`) — просто байты без объявленной
кодировки. Старые редакторы писали их в системной кодировке (для русских
названий — cp1251: «скрипки» показывалось как `ñêðèïêè`), новые — в UTF-8.
Лёгкий парсер дорожек в `web/synth.js` теперь декодирует имя через
`decodeMidiText`:

1. строгий UTF-8 (`TextDecoder("utf-8", { fatal: true })`) — если проходит,
   берём его;
2. иначе считаем долю латинских букв с диакритикой (диапазон 0xA0-0xFF) в
   cp1252-декодировании: **больше половины → cp1251, иначе cp1252**.

Логика: русский текст, прочитанный как cp1252, почти целиком состоит из таких
букв (`ñêðèïêè` — 7 из 7), а настоящий западный текст — нет («Café solo» — 1 из
4, «Mélodie» — 1 из 6). Порог 0.5 выбран по этим двум замерам.

Декодирование живёт в UI (а не в C++-парсере): панель дорожек — единственный
потребитель имён, синтез их не использует, а браузер даёт `TextDecoder` с
cp1251 бесплатно. Размер WASM от этой правки не меняется вовсе.

## Замер

`.scratch/encoding-probe.mjs` (10/10) — берёт функции из реального `web/synth.js`
и прогоняет их на собранных MIDI-файлах: cp1251 «скрипки», «Piano скрипки»,
«Дорожка №1 (соло)»; UTF-8 «Партия флейты»; cp1252 «Café solo», «Mélodie»
(не «Cafй»); ASCII «Bass & Drums»; три дорожки в разных кодировках в одном
файле; отсутствие U+FFFD; пустое имя. Дополнительно в браузере
(`.scratch/ui-check84.mjs`): панель показывает «скрипки» вместо `ñêðèïêè`.

## Ограничения (осознанные)

- Эвристика бинарная и без статистики языка: имя в KOI8-R, MacRoman или Latin-2
  будет прочитано как cp1252 (для кириллицы это по-прежнему кракозябры, но уже
  другие). CP866 (DOS-кодировка) тоже не распознаётся.
- Западное имя, состоящее ПОЧТИ ЦЕЛИКОМ из диакритики (например «Àéîü»), может
  быть принято за cp1251. На реальной практике таких названий нет.
- Если в будущем понадобится точнее — следующий шаг не «ещё один порог», а
  проверка кандидатов по словарю/частотам букв; делать это сейчас смысла нет.
