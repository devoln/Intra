# Worklog Discipline

Create a worklog only when the task needs one.

## Create a worklog if any of these are true

- The task is medium/high risk.
- The task will likely span multiple steps or sessions.
- The task touches multiple subsystems.
- The task needs a handoff.
- The task will end with a human verification checklist.
- The task has real risk of scope creep.

## Skip the worklog if all of these are true

- The task is low risk.
- The task is local and short.
- It fits in one session.
- It is fully verified by fast automatic checks.
- It does not need a handoff or human follow-up.

## Keep it lean

Default structure:
- Task
- Risk level
- Loaded skills
- Milestones
- Invariants if needed
- Deterministic checks
- Needs Human Verification
- Session log
- Surprises
- Next-step handoff

Do not turn the worklog into a thesis.
For most tasks, short is better.

## Update cadence

Update the worklog:
- after planning;
- after each meaningful milestone;
- when verification results arrive;
- when you discover a surprise;
- before ending the session.

## End state

At task end, make sure the worklog clearly shows:
- what was done;
- what passed;
- what still needs human verification;
- what reusable lesson should be extracted.
