# Решение

## Что решено

`MidiSynth::FastForward` (веб-UI: `SourceFastForward`) делает ровно две вещи:

1. **Гасит всё звучащее** — по 16 каналам `OnAllNotesOff` (то есть `NoteRelease`
   каждому голосу). Именно `NoteRelease`, а не мгновенное обнуление: релиз
   доигрывается ≈0.5 с и гаснет сам, поэтому перемотка не даёт щелчка.
2. **Пропускает события файла до цели**, читая состояние каналов (CC7, панорама,
   программа, педаль), но **не создавая нот** (`mSkippingEvents`). Фидбек в UI
   при этом не пишется, чтобы панель дорожек не подсвечивала пропущенное.

Итог: после перемотки играют только ноты, начинающиеся ПОСЛЕ цели — обычное
поведение MIDI-секвенсера. Ноты, удерживаемые на целевой позиции (пады,
педальное пиано), не дозвучивают: их услышит следующий note-on. Назад — по-прежнему
пересоздание источника в веб-UI (состояние потока необратимо).

Это решение владельца («Нельзя было просто убить все семплеры и мотать?
Запускать только ноты, которые идут после перемотки, это норм для MIDI») и
откат промежуточного варианта из `20260914-SeekReviveHeldNotes` (дозвучивание
удерживаемых нот через список `mSkipHeld`).

## Почему откат (замеры)

- **Размер.** Канон: Update 82 — 216 997 → Update 83 (дозвучивание) — 218 402
  (+1 405) → Update 84 (откат) — **217 008** (−1 394). Сборка с
  `INTRA_UI_METERS=OFF`: 216 014 → 217 419 → **216 025**.
- **Фикс нулевой громкости ни при чём.** Разовый замер с временно отключённым
  живым слоем CC7 (зажим `BornCC7For`, `ChannelGain = 1`, пустой
  `UpdateChannelGain`) даёт 216 744, то есть весь живой слой громкости канала
  стоит ≈264 байта (0.12 %). Прирост дал именно путь перемотки.
- **Артефакт, который мешал владельцу.** Дозвучивание переатаковывало ноты,
  рождённые в пропущенном участке: на Chopin с педалью пик сразу после перемотки
  доходил до 0.510 против 0.157 при обычном воспроизведении. После отката —
  0.091, то есть тише обычного воспроизведения (остальные реальные файлы:
  tous les garçons 0.761 против 0.798, celine 0.070 против 0.133; клиппинга нет).
- **«Взрыва» нет и без дозвучивания** (измерено): 30 нот в пропущенном участке
  дают после перемотки пик 0.000000; всплеска на самой перемотке нет (0.084
  против 0.107 до неё).

## Чем платим

- Длинная нота (пад, педальная нота), удерживаемая на цели, замолкает: чтобы
  услышать её снова, нужен новый note-on. Так ведёт себя и обычный секвенсор при
  перемотке, и владелец выбрал это поведение как норму для MIDI.
- Релиз нот, звучавших до перемотки, доигрывается ≈0.5 с после неё.

## Что осталось верным

- Обычное воспроизведение не изменилось ни на байт: PCM реального файла и живого
  источника совпал с прошлой сборкой (`.scratch/render-ident84.mjs`, md5
  `0c6cf88eea87` и `af98f04103f9`).
- Живой слой громкости канала (CC7/мьют) после перемотки работает как раньше
  (CC7 127 → 32 на звучащей ноте: пик 0.153 → 0.039).
- Мгновенность сохранена: 0.9 мс (вперёд) и 0.8 мс (назад, с пересозданием
  источника) на событии `input` в браузере.
